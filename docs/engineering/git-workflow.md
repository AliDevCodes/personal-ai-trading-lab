# Git Workflow

- Keep changes focused and reviewable.
- Use descriptive commits that state the intent of the change.
- Review for scope, module boundaries, deterministic financial behavior, tests, documentation, and secret exposure before merging.
- Do not commit credentials, generated build artifacts, local IDE state, or unrelated formatting changes.
- Use pull requests or equivalent reviewable change sets when collaboration requires them; branch naming and release conventions are TBD.
